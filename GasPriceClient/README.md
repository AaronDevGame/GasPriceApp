# GasPriceClient

This directory is reserved for one Expo/React Native client targeting web, iOS, and Android. The Expo project has not been initialized yet.

The shared app, routes, components, API client, and configuration will live at this directory's root. The `web/` directory is for web-only code or assets. The `ios/` and `android/` directories are reserved for native projects generated by Expo when those builds are needed. They are not separate apps or Git branches.

Native build caches and local signing files are ignored. Before generating native projects, choose whether to commit the generated `ios/` and `android/` source or regenerate it from Expo configuration; the current ignore rules leave either choice open.

## Guest authentication (1.0.0)

Native uses Expo SDK 57 SecureStore for a single session record containing both
secrets and the public UUID v4 appInstanceId. Configure `EXPO_PUBLIC_API_URL` with
the Cloudflare Worker origin shown in `.env.example` before starting Expo. HTTP
is accepted only in native development builds for local testing. Public Expo
environment variables must never contain secrets. Rebuild the iOS/Android
development client after installing the new native modules (`npx expo run:ios`,
`npx expo run:android`, or an EAS development build). SecureStore is device-local;
do not promise guest recovery after uninstall, backup restore, or clearing app data.

Web always calls relative API paths with `credentials: 'same-origin'`. Serve the
static export and API through one HTTPS origin. Route `/auth/*`, `/player/*`,
`/fuel-prices*`, and `/ai/*` to the backend; route remaining paths to the Expo web
export. Keep `/admin/*` private. No credentialed cross-origin deployment is enabled.
Do not add wildcard CORS, make cookies JavaScript-readable, or disable Secure to
work around deployment problems.

The proxy must preserve the public Host and pass the HTTPS scheme from a trusted
proxy. Configure the backend's `ReverseProxy:KnownProxies` or `KnownNetworks` for
only your actual ingress (see the existing Render defaults). Terminate TLS at the
proxy in production. Persist/share ASP.NET Data Protection keys across backend
instances so CSRF tokens remain valid during restarts and load balancing. Exclude
API responses from CDN/service-worker caching and redact cookies/auth headers from
proxy logs. Use a trusted localhost HTTPS certificate for local browser testing.

For example, with Caddy on the same machine as the backend (configure loopback as
a trusted reverse proxy), a development proxy can serve the export as follows:

```caddyfile
localhost:8443 {
    tls internal
    @api path /auth/* /player/* /fuel-prices /fuel-prices/* /ai/*
    handle @api {
        reverse_proxy 127.0.0.1:8080
    }
    handle {
        root * /absolute/path/to/GasPriceApp/GasPriceClient/dist
        try_files {path} {path}.html /index.html
        file_server
    }
}
```

Run `npx expo export --platform web` before serving `dist`. For Metro development,
replace the static-file handler with a reverse proxy to Expo's web server, retaining
the same HTTPS origin and API route handlers.

On startup the app checks the saved session before displaying player data. Native
renewal sends `X-Guest-Credential` only to `/auth/guest/login`; protected calls send
Bearer plus `X-App-Instance-Id`. Web uses `/auth/browser/status`, `/auth/browser/csrf`,
and `/auth/browser/guest/login`, with both authentication secrets confined to
HttpOnly cookies. Only the separate CSRF request token is held in JavaScript memory.

Sign out revokes access, retains the guest credential, and requires explicitly
choosing **Continue as guest**; restarting/reloading does not sign the user back in.
Browser guest cookies persist for 365 days and are renewed on login. If identity
verification fails, **Create a new guest instead** requires a second confirmation
and replaces the locally saved identity; it does not reclaim the old account by ID.
Network failures preserve saved credentials and show a retry state.

Verification: `npm run lint`, `npm run typecheck`, `npm run test:auth`, and
`npx expo export --platform web`.
Backend integration instructions are in `GasPriceBackend/tests/guest_auth_smoke.py`.
